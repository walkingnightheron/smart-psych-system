# 04 部署复现手册与答辩分工指南

> 目标：队友拿到源码后，可按同一种方式稳定复现；答辩时每名成员都能独立启动、操作、解释并完成一个小改动。  
> 项目实际运行基线：**JDK 17、Spring Boot 3.3.5、Node 18+、Maven、npm**。早期蓝图中的 JDK 21 不作为当前工程强制要求。

## 1. 两种启动与异地复现模式

| 对比项 | 模式 A：`demo` 零外部中间件模式 | 模式 B：`default` 完整中间件模式 |
| --- | --- | --- |
| 适用场景 | 队友干净电脑、课堂演示、离线快速验收 | 验证 MySQL/Redis/RabbitMQ 真联通、持久化和真实队列 |
| 必需运行时 | JDK 17、Node 18+ | JDK 17、Node 18+；MySQL 8.0+、Redis 7、RabbitMQ 3.13 |
| 构建工具 | Maven 3.9+、npm | Maven 3.9+、npm |
| 额外环境 | **不需要** Docker、MySQL、Redis、RabbitMQ | Docker Desktop + Compose，或本机安装三类服务 |
| 数据库 | H2 内存库 `MODE=MySQL`，启动执行 `schema-h2.sql` | MySQL `psych_assessment`，由 `init.sql` + `seed.sql` 建表和导入 |
| 缓存 | 配置 `redis-with-fallback`；无 Redis 时自动内存降级 | 默认同样为 `redis-with-fallback`，可通过 `CACHE_MODE=redis` 严格校验 Redis |
| 消息传输 | `app.mq.transport=async`，`reportTaskExecutor` 本地线程池；RabbitListener 不启动 | 默认 `rabbit` + RabbitListener，真实 Exchange/Queue/Binding |
| 种子数据 | `app.seed.enabled=true`，空用户库时自动注入 7 账号、1 卷 v1、2 活动、2 份预置答卷/报告 | 默认 `SEED_ENABLED=false`；由 SQL 脚本导入同一教学数据集 |
| 数据生命周期 | 进程结束即清空，重启恢复干净初始现场 | MySQL volume/本机库持久化；重复演示会积累新业务数据 |
| 初始统计 | 活动 1 为 3 人名单 2 份有效答卷，66.67% | 同一口径 66.67% |
| 自动化测试 | `mvn test` 使用 demo + H2，并强制内存缓存 | 同一 JUnit 命令不依赖已启动 default 中间件 |

> “零外部依赖”是指**不需要外部中间件服务**，不是不需要源码构建工具。没有 Maven 时应先安装/配置 Maven，再按本手册运行；不能直接执行仓库中不存在的 Maven Wrapper。

## 2. 模式 A：3 分钟标准复现（`demo` profile）

### 2.1 环境自检

```bash
java -version   # 应为 17.x
mvn -version    # 确认 Maven 能使用该 JDK
node -v         # 建议 18 或更高兼容版本
npm -v
```

将三个终端的工作目录都定位到项目根目录。Windows 路径含中文可以运行，但请完整引用 profile 参数，避免 PowerShell 对参数解析产生差异。

### 2.2 终端 1：启动后端

```bash
cd backend
mvn spring-boot:run "-Dspring-boot.run.profiles=demo"
```

也可以使用环境变量，二选一，不要重复冲突配置：

```bash
# Bash
export SPRING_PROFILES_ACTIVE=demo
mvn spring-boot:run

# Windows PowerShell
# $env:SPRING_PROFILES_ACTIVE = "demo"
# mvn spring-boot:run
```

启动过程依次完成：H2 建表 → `DemoDataInitializer` 注入种子 → 开放 8080。当前 `demo` 使用 `redis-with-fallback`，因此未安装 Redis 时可能看到连接失败的 warn，随后应是内存降级而不是启动失败；工作台的真实运行后端可作为核验依据。

健康检查：浏览器访问 `http://localhost:8080/api/health`，应看到统一响应且 `data.status` 为 `UP`。

也可以先构建可执行 JAR，之后复制 JAR 到其他机器只需 JDK 17 运行（构建当下仍需 Maven）：

```bash
cd backend
mvn clean package
java -jar target/psych-backend-0.1.0-SNAPSHOT.jar --spring.profiles.active=demo
```

### 2.3 终端 2：启动 PC 管理端

```bash
cd pc-web
npm install
npm run dev
```

访问：`http://localhost:5173/login`。开发服务器把所有 `/api` 请求代理到 `http://localhost:8080`。

### 2.4 终端 3：启动 H5 参与端

```bash
cd h5-app
npm install
npm run dev:h5
```

访问：`http://localhost:5174/#/pages/login/login`。H5 开发配置同样代理 `/api` 到 8080。

### 2.5 一键验收检查

1. `admin01 / 123456` 可登录 PC。
2. 活动 1 初始显示 3 人名单、2 人完成、66.67%。
3. `20260003 / 123456` 可登录 H5、读取 6 题并提交，报告由 PENDING 自动到 SUCCESS。
4. 同一学生重复提交出现 409 弹窗并能回原报告/记录。
5. 重启后端后，之前新增的内容消失，活动 1 自动恢复 66.67%，适合重置下一位答辩人的演示现场。

## 3. 模式 B：MySQL + Redis + RabbitMQ（`default` profile）

### 3.1 统一环境变量

先复制模板用于本机管理，但**不要提交 `.env`**：

```bash
cp .env.example .env
# Windows PowerShell 也可：Copy-Item .env.example .env
```

请逐项替换模板中的占位口令和 `JWT_SECRET`。变量如下：

| 变量 | 完整模式常用值（示例而非生产密钥） | 说明 |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | `default` 或不显式设置 | default 从 `application.yml` 读取 |
| `DB_URL` | `jdbc:mysql://localhost:3306/psych_assessment?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&characterEncoding=utf8` | 与实际库名、地址一致 |
| `DB_USERNAME` | `root` 或专用最小权限账号 | 教学本地可用 root，真实部署应专用账号 |
| `DB_PASSWORD` | 本机实际密码 | 必须与 MySQL 初始化/本机账号一致 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | `localhost` / `6379` / 按实际设置 | Redis 管理信息 |
| `RABBIT_HOST` / `RABBIT_PORT` | `localhost` / `5672` | AMQP 服务 |
| `RABBIT_USERNAME` / `RABBIT_PASSWORD` | Docker 默认 guest/guest 或自定义 | 与 RabbitMQ 初始化一致，真实部署勿沿用 guest |
| `JWT_SECRET` | 自己生成至少 32 字节的随机字符串 | 勿使用 `.env.example` 占位符或源码教学 fallback |
| `JWT_EXPIRE_HOURS` | 默认 24 | 可按课堂需要设置 |
| `CACHE_MODE` / `CACHE_TTL_SECONDS` | 默认 `redis-with-fallback` / `1800` | 验证 Redis 真联通可设 `redis` 严格模式 |
| `MQ_TRANSPORT` / `MQ_LISTENER_AUTO_STARTUP` | 默认 `rabbit` / `true` | 完整模式保持 rabbit 与监听开启 |

**重要：** `.env.example` 是变量清单，根目录 `.env` 会被 Docker Compose 用于变量替换，但 `mvn spring-boot:run` 不会自动加载根目录 `.env`。运行后端前必须在同一终端显式设置变量，例如：

```bash
# Bash（请替换尖括号，不要原样使用）
export DB_PASSWORD='<你的MySQL密码>'
export JWT_SECRET='<至少32字节的随机密钥>'
# 其他非默认变量同样 export...
mvn -f backend/pom.xml spring-boot:run

# PowerShell 对应写法：
# $env:DB_PASSWORD = '<你的MySQL密码>'
# $env:JWT_SECRET = '<至少32字节的随机密钥>'
# mvn -f backend/pom.xml spring-boot:run
```

### 3.2 方式 B1：Docker Compose 启动三类中间件

在仓库根目录执行：

```bash
docker compose up -d
docker compose ps
```

容器与端口：

| 服务 | 容器 | 端口 | 数据/管理入口 |
| --- | --- | --- | --- |
| MySQL 8.0 | `psych-mysql` | 3306 | 数据库 `psych_assessment`；root 密码取 `${DB_PASSWORD:-psych_dev_pass}` |
| Redis 7 Alpine | `psych-redis` | 6379 | 热点键 `psych:qver:*`、`psych:act:*` |
| RabbitMQ 3.13 Management | `psych-rabbitmq` | 5672、15672 | 管理台 `http://localhost:15672`，本地默认 guest/guest 或 `.env` 自定义值 |

MySQL 使用命名卷 `psych_mysql_data`，并将 `init.sql`、`seed.sql` 只读挂载到 `/docker-entrypoint-initdb.d/`。**脚本只在数据目录首次初始化时自动执行**，重复 `up` 不会重新 seed。若使用已有卷，应核验数据库已有 9 表和教学数据，不要误以为改了 SQL 就会自动重导入。

后端保持 default 启动：

```bash
cd backend
mvn spring-boot:run
```

PC 和 H5 的启动方式与模式 A 完全相同。RabbitMQ 中可核查：

- Exchange：`psych.report.exchange`（Direct，durable）
- Queue：`psych.report.generate.queue`（durable）
- Routing Key：`psych.report.generate`
- 消息体：答卷 `sheetId`

### 3.3 方式 B2：本机 MySQL / Redis / RabbitMQ

先启动三类本机服务，再使用 MySQL 客户端执行：

```sql
CREATE DATABASE IF NOT EXISTS psych_assessment
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE psych_assessment;
SOURCE ./init.sql;
SOURCE ./seed.sql;
```

`SOURCE` 路径以 MySQL 客户端当前目录为准；也可替换为项目内 SQL 的绝对路径。导入后核验：

```sql
USE psych_assessment;
SHOW TABLES; -- 应为 9 张核心表
SELECT username, role, status FROM sys_user ORDER BY id;
SELECT activity_id, COUNT(*) AS roster_count
FROM activity_participant WHERE activity_id = 1 GROUP BY activity_id;
SELECT activity_id, COUNT(*) AS completed_count
FROM answer_sheet WHERE activity_id = 1 GROUP BY activity_id;
```

之后按 3.1 在同一后端终端设置连接变量并执行 `mvn spring-boot:run`。default 不自动 seed，故 SQL 是必须步骤。

### 3.4 可重复的测试现场

- 模式 A 最推荐逐人答辩：重启后端即恢复种子。
- 模式 B 会保留新增的 v2、答卷和报告。要恢复初始 66.67%，应使用预先备份的干净库。
- 仅对**可丢弃的教学 Docker 数据卷**，可在知悉全部教学数据会删除的前提下执行 `docker compose down -v`，然后 `docker compose up -d` 触发首次脚本初始化。真实数据库禁止用该方式“清理现场”。本手册不在任何章节建议对真实数据执行 destructive reset。

### 5.3 演示后的核验问题

1. 为什么发布 v2 后活动 1 的学生仍读 v1？——活动持有固定 `questionnaire_version_id`，草稿与快照是不同数据源。
2. 为什么 409 必须带原 IDs？——避免学生重填，H5 可准确回到本人原报告/原答卷。
3. 为什么已交卷但报告 PENDING 也算完成？——完成率统计有效答卷落库，报告状态是另一维度；但结果分布只统计 SUCCESS。
4. 为什么清缓存后第一次是 MISS、第二次是 HIT？——读穿缓存首次回源并 PUT，后续读取同一 version/activity 键命中；关闭时则主动 EVICT 且提交实时查库。

## 6. MQ 故障演示（REQ10 扩展）

在干净演示现场，先取得 `admin01` Token，再通过 Apifox/Postman/curl 调用管理端运维接口。请求头均带 `Authorization: Bearer <admin01-token>`：

```text
POST /api/admin/mq/fault?sendFailure=true
```

随后用 `20260003` 正常提交活动 1。期望：接口仍 200，原答卷完整，报告 PENDING，管理员报告详情的 `lastError` 包含 `MQ消息投递失败`。这不是“提交失败”，而是“提交成功、异步投递受控失败”。

复位并补偿：

```text
POST /api/admin/mq/fault?reset=true
POST /api/admin/reports/{reportId}/retry
```

成功后报告转 SUCCESS，统计对应状态更新。计算故障可用 `POST /api/admin/mq/fault?consumeFailure=true` 注入；累计 3 次后应为 FAILED、retryCount=3 且不继续自动增长。管理员人工核查后使用 `POST /api/admin/reports/{reportId}/retry?reset=true` 重置计数再补偿。学生 H5 只能重试本人，不具备 reset 权限。

每次故障演示末尾必须调用 reset，并检查 `GET /api/admin/mq/status` 中 `simulateSendFailure=false`、`simulateConsumeFailure=false`，防止污染下一位成员现场。

## 9. 个人答辩高频抽问应答卡片

| 高频问题 | 30 秒准确回答 |
| --- | --- |
| 为什么不让历史活动关联正在编辑的草稿？ | 草稿随时可变，无法复核旧答卷。发布时把完整题目、选项分值和计分规则写入 version 表，活动固定 versionId，再发 v2 也只是一行新快照；隔离测试同时回读 H5、v1/v2 和活动绑定。 |
| 401、403、409 如何区分？ | 401 是“没有可信登录身份”（缺/坏/过期 Token、禁用用户）；403 是“身份已识别但角色或数据范围不允许”；409 是同一学生同一活动已经存在有效答卷，响应还携带原 IDs。 |
| 有预检为什么还需要唯一索引？ | 预检与插入之间存在竞态。`uk_submit_once(activity_id,user_id)` 是数据库最终互斥条件；两个并发请求只能一个成功，另一个捕获 DuplicateKeyException 并转成 409。测试 9 并发结果为 1×200、8×409。 |
| 为什么不能用缓存判断活动能否提交？ | 缓存可能保留旧 PUBLISHED。提交服务直接读取活动实时行，再校验状态和时间窗；即使测试人为回写旧缓存且详情确实 HIT，CLOSED 提交仍 400 且无答卷。 |
| 为什么一定是 AFTER_COMMIT？ | 事务可能回滚，提前投递会让消费者处理不存在的数据。事件虽在事务内发布，监听器只在真正 COMMIT 后执行；明细故障回滚时不会有报告任务。 |
| AFTER_COMMIT 出错后 last_error 为什么用 REQUIRES_NEW？ | 错误落库不能依赖已完成或可能标记 rollback-only 的原事务。独立 Bean 通过 Spring 代理开启新事务，并单独捕获持久化异常，避免二次异常掩盖 MQ 原异常。 |
| 消费幂等只靠 Redis 吗？ | 不依赖 Redis。`assessment_report.sheet_id UNIQUE` 保证一卷一报告；按 sheetId JVM 锁串行化本实例消费；SUCCESS 直接跳过且不改分数/生成时间，数据库最终只保留一报告。 |
| 反向计分怎样算？ | 本卷 A～D 原分 1～4，reverseMaxPlusMin=5，所以反向题有效分为 4～1。正向原样；系统支持自定义基数，缺省回退到该题选项 max+min；保存时 answer_item.raw_score 实际是转换后的有效分。 |
| 完成率与报告状态为何要分开？ | 学生事务提交成功就说明已交卷，即使报告稍后失败也不能说没交。因此完成数看 answer_sheet；只有 SUCCESS 才有真实区间和维度均值，PENDING/FAILED 单独计数，空名单完成率为 0.00。 |
| 两份种子报告的维度均值怎么来？ | 4、5 号学生 STRESS 为 3、6，均值 4.50；MOOD 为 2、5，均值 3.50；SLEEP 为 4、6，均值 5.00。第三份全 A 报告加入后变为 STRESS 3.67、MOOD 4.00、SLEEP 5.00。 |
| 为什么不使用物理外键？ | 用逻辑 ID 统一 MySQL/H2 双模式，避免草稿与历史快照、同步提交与异步错误补偿被不恰当级联绑死。数据库仍用唯一键，应用做存在性/角色/名单/版本校验，事务防半写，自动化检查孤儿和重复；不能把它说成“无需关系管理”。 |
| demo 的 39 项通过是否证明真实 RabbitMQ/Redis 已测？ | 不能等同。39 项证明 demo 下 HTTP、服务、H2、内存缓存和本地 async 的应用链路断言通过；真实 default 模式还要单独验证容器联通、队列拓扑、持久化及故障恢复。 |
| 教师正式问卷下来后怎么替换？ | 不改 Java/DDL，通过 PC 录入草稿并配置选项分值、维度、正反公式和区间，再发布新版本绑定新活动。旧活动继续用旧快照。新的标准答案/边界应重新核验测试预期，不能把教学模拟结论冒充正式量表通过结论。 |

## 10. 常见启动问题定位

| 现象 | 优先检查 | 处理方式 |
| --- | --- | --- |
| 8080/5173/5174 端口占用 | 对应服务是否已启动或进程残留 | 复用已启动服务或释放端口；后端可设 `SERVER_PORT`，同时修改代理 |
| `mvn` 不是命令 / JAVA_HOME 不符 | `mvn -version` 输出 | 配置 Maven 和 JDK 17，不要误装 MySQL 来解决构建问题 |
| default 数据库拒绝连接 | MySQL 是否启动、库名/账号/密码端口、DB_URL 是否在同一后端终端设置 | 先修连接；本机无中间件时改用 `demo`，不要期待 default 自动变 H2 |
| 日志有 Redis warn | `CACHE_MODE` 与工作台 `activeBackend` | `redis-with-fallback` 可继续内存演示；严格 `redis` 模式则会明确失败，不能混称 |
| 提交后一直 PENDING | `GET /api/admin/mq/status`、RabbitMQ 连接、报告 lastError、是否残留故障开关 | default 确认 `rabbit/true` 与监听；demo 应为 `async`；复位故障后受控重试 |
| 种子账号无法登录 | 当前运行哪个库、是否已导入 seed、旧 volume 中哈希是否陈旧 | 核对 `sys_user` 哈希与当前 seed；demo 重启重建；不要修改 AuthService 绕过密码验证 |
| 初始统计不是 66.67% | 是否现场已有第三卷或旧 MySQL volume | 新模式 A 重启；完整模式用受控干净库；不要手改完成率公式 |
| H5 提示活动未开始/截止 | 系统真实时间、活动状态和 start/end | 创建真实有效的当前时间窗活动，不用前端隐藏错误代替后端拦截 |
| 页面 401 连环跳转 | Token 过期、JWT_SECRET 启动后变更、账号被禁用 | 重新登录；确保签发与解析使用同一密钥；两角色不要混用端点 |
